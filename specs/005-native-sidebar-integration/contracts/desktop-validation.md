# Desktop Validation Contract

**Status**: Required future automation; no probe or acceptance result is implied.

## Bootstrap and dependency boundary

Use existing `@vscode/test-electron` provisioning and installed-VSIX harness. Evaluate exact test-only `playwright@1.64.1` (Apache-2.0; npm metadata inspected 2026-10-24), using its Electron API and test assertions. Do not add it to extension dependencies or VSIX contents. Freeze the dependency and transitive graph in the existing pnpm lockfile during implementation. No separate browser or production server is required for the Electron candidate.

The bootstrap launches the actual downloaded Desktop binary and disposable profile, reaches the existing Angular custom editor, performs real pointer/keyboard insertion, independently reads resulting host XML, captures workbench/webview screenshots and accessibility semantics, and proves shutdown/cleanup. Record executable version/build/hash, driver version, launch arguments, frame discovery and each capability result. The official Electron API is experimental and can fail when the binary disables Node CLI inspection; do not modify the product binary/fuses to manufacture a pass. Failure requires a documented driver/harness adaptation and keeps mandatory UI cases blocked.

## Root command interface (to implement)

- `pnpm test:e2e -- --probe`: bootstrap plus native-drag public-API feasibility record; nonzero for missing mandatory driver capabilities. An evidenced unsupported native drag is a capability result, not a skipped activation test.
- `pnpm test:e2e`: AT-01–09 real functional/keyboard/lifecycle/offline cases appropriate to the platform. Reuse pure and host suites rather than treating direct session calls as UI proof.
- `pnpm test:e2e -- --packaged`: run applicable installed-VSIX journeys against the packaged candidate, excluding the development extension.
- `pnpm test:visual`: compare committed reference PNGs and semantic/geometry/contrast assertions against the fixed reference environment. Missing baselines or skipped required assertions fail.

These commands do not exist at planning time. Their runner must support the documented arguments, bounded waits and nonzero failure propagation. Build/package prerequisites are in [quickstart.md](../quickstart.md).

Add required jobs to the existing CI aggregate and reusable release quality call graph; preserve frozen installs, existing checks and same-VSIX publication rules. Resolve stable to an exact recorded binary for each run.

The release canonical job rebuilds its own VSIX. Run applicable installed E2E/security/visual checks on those exact bytes before `release-artifact.js`, or bind equivalent executed evidence to that exact digest. Earlier matrix checks on another artifact do not certify the canonical candidate. Keep publication's existing prebuilt artifact/digest handoff; the driver never enters publishing jobs or the VSIX.

Visual references use an Ubuntu 24.04 image with recorded image revision/fonts, exact VS Code `1.142.0` build/hash, fixed driver, 1440 × 1000 display, DPR 1, English locale and UTC. Baseline generation is explicit, reproducible and checked against layout/contrast oracles; CI never auto-updates images.

Trusted and restricted-workspace profiles must be separate; do not pass `--disable-workspace-trust` for restricted tests. Provision dependencies before blocking outbound traffic. Observe attempted outbound access for the host process tree and webview, not only successful requests or browser routing; validate the observer with a test-harness positive control outside report workflows. Missing platform observation coverage fails the relevant case.

## Independent assertions and evidence

Use [automated-validation.md](../automated-validation.md) AT-01–09 as the complete traceability matrix, including all edge cases and inherited regression rows. Expected hierarchy/source slices, exact text states and geometry are fixture oracles independent of the code under test. Real input must produce real native/Angular rendered state; test-only hooks may observe or delay races but may not replace actions or fabricate acceptance.

Record candidate commit as provenance, the candidate input fingerprint and scoped working-tree patch digest when applicable, VSIX SHA-256, fixtures and hashes, assertion IDs, requirement/scenario/edge/SC references, platform/OS image, Desktop/driver/build versions, theme/fonts/locale, display/DPR/interface scale/report zoom, outcomes and artifact paths. Probe outcomes distinguish passed, unavailable-with-evidence, failed and unrun. Secrets, image payloads and query bodies are excluded from logs.

### Candidate fingerprint and evidence invalidation

- Before execution, freeze a versioned input manifest of sorted repository-relative paths and SHA-256 hashes of exact file bytes, including relevant tracked and untracked files. Hash its canonical UTF-8 representation to obtain the candidate input fingerprint. Include production source/assets, manifests/lockfile, build/package/release configuration and scripts, test runners/assertions, fixtures/expected oracles, committed visual baselines and metadata, coverage mappings, and normative acceptance/validation contracts. Record manifest inclusion/exclusion rules; discovery must detect additions/deletions, not only changes to previously listed files. A dirty-checkout patch digest covers this same input boundary, including untracked inputs; a whole-worktree diff is not the fingerprint.
- Exclude generated evidence records (including the manifest record itself), logs/traces, actual/diff captures, build/test outputs and generated VSIX files from the input hash. Expected fixtures/baselines are inputs even when initially generated; freeze them before the validating run. Record generated VSIX bytes separately by SHA-256. Exclude narrative documentation, task checkboxes and approval/status bookkeeping only when they do not change requirements, assertions, coverage, configuration or normative contracts. Changing a rule hidden in documentation is an input change, not bookkeeping.
- Writing results, summary JSON or task completion marks cannot invalidate their own evidence. Such files are not trusted as proof by their presence: verify executable assertion IDs, outcomes and artifact integrity. Record each artifact's digest outside that artifact's own content; missing or altered artifacts invalidate the dependent evidence.
- Recompute the input manifest at run completion and final aggregation. Any included input addition/deletion/change, including an assertion, fixture, baseline or normative contract change, makes previous candidate evidence ineligible for the new candidate; rerun all mandatory applicable gates before declaring it validated. Preserve older records as historical outcomes, not current passes. An environment/display/theme/driver change requires fresh evidence for the changed environment; it does not certify other matrix entries. A changed VSIX digest requires fresh applicable installed-artifact checks on those exact bytes, even if source inputs match. Never mix candidate fingerprints or substitute evidence from another VSIX digest.
- A commit change is provenance, not by itself a byte change: bookkeeping-only commits may retain an identical input fingerprint and VSIX evidence only after automated manifest/artifact verification. This does not waive constitution VI: release-tag CI still checks the exact tagged commit with frozen dependencies, runs all required gates and verifies the canonical rebuilt VSIX before publication.
- Automated evidence tests must prove that recording evidence/status leaves the fingerprint unchanged; production, test, fixture, baseline, contract and relevant untracked-input changes/additions/deletions invalidate it; modified/missing artifacts are rejected; changed environments/VSIX bytes cannot reuse incompatible results; and missing/failed/unrun mandatory assertions still fail final aggregation. No manual approval can override invalidation.

Required samples: 100 selection alternations (≥95 visibly correct within 200ms), 100 document/view switches, 50 stale/duplicate/closed-target races, 100 interaction frame series (≤1 screen-pixel unintended drift), ≥12 preservation reports and 20 individually reversible mixed edits. Placement tolerance is ≤0.01pt; center tolerance is ≤1 CSS px with unchanged zoom. Capture raw input-to-presented-state samples with sampling resolution; host completion/animation callbacks alone are insufficient. Contrast is ≥4.5:1 normal text and ≥3:1 essential boundaries/focus/selection from composited rendered colors.

Upload expected/actual/diff images, trace/accessibility/focus records, XML preservation assertions, race logs, network-attempt records and timing/frame samples with minimum artifact permissions. Every required test must pass for the same candidate/environment before feature validation; missing/failed evidence blocks delivery. Only native drag may be explicitly unavailable, with recorded probe evidence and passing activation/fallback coverage.
